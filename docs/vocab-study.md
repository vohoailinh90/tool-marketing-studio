# Vocabulary study

The owner studies English (today from *Never Split the Difference*) and Japanese in one standalone
page, `vocab/vocab_standalone.html`. New words are explained in a Claude Code chat and then folded into
that page by `scripts/vocab.py`. This document is the whole picture; the session's instructions are in
`.claude/skills/vocab-study/SKILL.md`.

## The flow

```
owner pastes a word or passage ──▶ Claude explains it, in Vietnamese      (writes nothing)
        … reads, asks more …
owner: "tổng hợp từ vựng"      ──▶ Claude collects every word it explained since the last aggregation
                                   ──▶ batch table ──▶ vocab.py add --dry-run ──▶ vocab.py add
                                   ──▶ vocab.py check ──▶ commit + push to the session branch
owner opens the page           ──▶ the new batch carries the "✨ Mới" mark
```

Explaining and storing are separate on purpose: the owner decides when a reading session is worth keeping,
and a word is never stored because it was merely mentioned.

## The store

The page is its own database: the words are one JSON array between two marker comments, so there is one
source of truth and nothing to keep in step.

```js
// <vocab-data> generated by scripts/vocab.py - add words with it, do not edit by hand
const SEED = [
  {"term": "elaborate on", "meaning": "…", "register": "Trung tính", "note": "…", "source": "Ch.2 Mirroring", "lang": "EN", "added": "2026-10-16"},
];
// </vocab-data>
```

- One entry per line, each ending in a comma: a batch is a clean diff and two batches rarely conflict.
- `term` is unique by `term_key` (NFKC, lower case, one space, a kana reading in brackets dropped), so
  `逸脱 (いつだつ)` and `逸脱` are one word and `trigger (v)` and `trigger` are two.
- `register` is one of five fixed values; `lang` is detected from the script; `added` is the batch date and
  drives the "Mới" mark (the words with the latest date).
- Size limits (`LIMITS` in the script) keep a passage out of the repository: a word, its meaning and one
  short example fit; a paragraph of a book does not.

## The commands

| Command | What it does |
|---|---|
| `check` | The store is valid and in the canonical form (CI runs it) |
| `add --from FILE [--source S] [--date D] [--dry-run] [--update]` | Add words from a 5-column table or a JSON backup. All or nothing |
| `find TERM [-a]` | Is it stored? Exit 1 when not |
| `list [--new] [--lang L] [--source S] [--format md\|json]` | Print words; `--new` is the latest batch |
| `stats` | Counts by language, register, source and batch |
| `remove TERM…` | Remove words by their exact term |
| `fmt` | Rewrite the block in the canonical form after a hand edit |

`add` skips a word already stored, reports one stored with different content (it never overwrites unless
`--update`), and warns when a word shares its headword with a stored one. Running it twice with the same
batch changes nothing.

## The page

- It lists the repository's words and adds the words kept **on this machine** (`localStorage`, key
  `vocab-linh-standalone-v2`, `{version, local}`). The repository's words are never copied into the
  browser, so a new batch always shows up when the file is replaced.
- The first load carries the words from the old key (`…-v1`, the whole list) that the repository does not
  hold into the new one, and leaves the old key untouched.
- A word kept on this machine can be deleted from the page. A repository word cannot; the owner asks Claude
  Code to remove it. Adding by hand or pasting a table refuses a word already present.
- "Cập nhật từ vựng" tab: the sentence to say to Claude Code, the words kept on this machine copied as a
  table (so they can be pasted into the chat and folded into the repository), and the older
  paste-a-table import for use without Claude Code.
- "Sao lưu" downloads only the words kept on this machine; `vocab.py add --from <that file>` accepts it.

## What it does not do

- **No spaced repetition.** The flashcards are a random pass over the filtered list, as before.
- **No sync of this machine's words** between browsers; they reach the repository through the chat.
- **No merge to `main` on its own.** A session commits and pushes to its branch. The page is on `main` only
  after a pull request is opened and merged, which the owner asks for; `CLAUDE.md`'s *Pull request
  lifecycle* applies to it. A CI run on a vocabulary-only pull request still runs the mutation check
  (`scripts/ci_changes.py` skips it only for the System Design store), because the page also holds app code.

## Checks

`python3 scripts/vocab.py check` and `tests/test_vocab.py` (unit tests plus the page in Chromium, skipped
where Chromium is not installed). `tests/mutations/vocab.yaml` and `vocab_page.yaml` switch each rule off and
require a test to fail.
